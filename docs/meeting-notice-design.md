# 会議の案内・アジェンダ配信と通知テンプレート 設計 v0.1（検討）

最終更新: 2026-11-05
前提: 議案台帳 `docs/proposal-ledger-design.md`、事前共有パッケージ（`app/meeting_package.py`）、
日程調整 `docs/schedule-poll-design.md`、対外連絡 `docs/external-notice-design.md`（配信のガードレール）

---

## 1. 背景

2026-11-05 の五役会で、会議の当日になってもアジェンダが配られていなかった。専務と専務AI が手作業で次を用意した。

| 作業 | 内容 |
|---|---|
| アジェンダ | 前回のアジェンダ（Google ドキュメント）をコピーし、題名・日時・場所・議案と資料のリンク・担当・次回会議を書き換えた |
| 意見書 | 意見書のスプレッドシートに、その回のシートを足した（議案ごとに「協議NN・議案名・意見の表」） |
| 開催案内メール | LOM 公式 Gmail から、案内文（日付・文書番号・差出人・日時・場所・議案・備考）を対象者へ送った |
| LINE | 会議体のグループに、全員へのメンション付きでアジェンダ・オンラインの URL・意見書のリンクを投稿した |

どれも、会議（日時・場所・オンラインの URL・対象者）と、上程される議案（台帳）がそろえば機械的に作れる。
ただ、文面・様式・文書番号の付け方・宛先の並べ方は LOM ごとに違う。そこでコードには書かず、**テンプレートとして LOM が登録する**形にする。

作業中に、次の失敗もあった。
- メールをプレーンテキストで作り、案内文の体裁（右寄せ・中央・字下げ）が崩れた
- ドキュメントをコピーすると「リンクを知っている全員」の共有が引き継がれない
- 作業に使ったアカウントがオーナーになった（LOM のアカウントに移せない）

## 2. 目的・範囲

- 会議ごとに「配信物」（アジェンダ・意見書のシート・開催案内メール・LINE 投稿）を自動で用意する。人は確認して送るだけにする。
- 文面は**通知テンプレート**（LINE の送信文・メールの送信文）として管理画面で登録・編集できる。既定のテンプレートは、どの LOM でも使える一般的な文面にする。
- 送るのは、いつも人の確認の後（議案の承認・対外連絡と同じ考え方）。自動で準備し、送ってよい時期になったら専務に知らせる。

範囲外（今回はしない）: 議事録の作成、出欠の集計の改善、会議後の意見書の取りまとめ。

## 3. 全体の流れ

```
会議（Event）＋上程議案（台帳）
   │  資料提出の締切の後（tick）／［配信物を準備する］ボタン
   ▼
配信物の準備（MeetingDispatch）
   ├ アジェンダ: LOM のひな形をコピーして差し込む（LOM のアカウントがオーナー）
   ├ 意見書: その回のシートを足す（任意）
   ├ メール: テンプレートで件名・本文を作る（宛先＝対象者のメール）
   └ LINE: テンプレートで本文を作る（送り先＝会議体のグループ）
   │  資料配信の締切の日（tick）に専務へ「配信の準備ができました［確認して送る］」
   ▼
管理画面「会議 › 案内・配信」で確認（プレビュー・宛先・足りない情報）
   │  ［メールを送る］［LINE に送る］（確認ダイアログに送り先の名前と人数）
   ▼
送信（ガードレール・記録・監査）
```

- 準備はやり直せる（議案が増えたら［配信物を更新する］）。アジェンダは同じファイルを更新し、URL は変えない。
- 送った後に直すとき: アジェンダはファイルを直せばリンクは同じ。メールと LINE は「修正の再案内」テンプレートで送り直す（件名の頭に「※修正再案内」）。

## 4. 通知テンプレート（汎用の核）

### 4.1 データ

```
noticeTemplates/{template_id}
  name            "五役会 開催案内メール" など（画面の表示用）
  channel         "email" | "line"
  purpose         "meeting_notice"（開催案内）| "agenda"（アジェンダ配信）| "correction"（修正の再案内）| …
  event_types     ["五役会", "理事会"]（このテンプレートを使う会議の種類。空なら全部）
  subject         件名（email のみ）
  body            本文（差し込み項目つき。email はレイアウト記法 §4.3）
  mention         "none" | "all" | "targets"（line のみ。全員／対象者へのメンション）
  is_default      その purpose・channel・event_type で最初に選ばれるもの
  updated_at, updated_by
```

- 既定のテンプレートはリポジトリに置き（`app/notice_templates/*.md`）、最初の起動で台帳に写す。LOM は管理画面で直したり、複製して種類ごとに作ったりする。
- 既定の文面は LOM 名・役職名・文書番号を差し込み項目にし、特定の LOM の言い回しを入れない。

### 4.2 差し込み項目

`{{…}}` で書く。保存のときに、知らない項目と閉じていないブロックを誤りにする（送るときに初めて気づくことをなくす）。式やコードは書けない。

| 項目 | 例 |
|---|---|
| `{{lom.name}}` `{{lom.short_name}}` | 一般社団法人○○青年会議所／○○JC |
| `{{fiscal_year}}` | 2027 |
| `{{event.title}}` | 第2回五役予定者会議 |
| `{{event.date}}` `{{event.date_wareki}}` `{{event.time}}` | 11月5日(木)／令和8年11月5日(木)／19:00〜21:00 |
| `{{event.place}}` `{{event.online_url}}` | オンライン／Meet の URL |
| `{{audience}}` | 五役予定者各位（会議体ごとの宛名。設定） |
| `{{sender.title}}` `{{sender.name}}` | 理事長予定者／（会員名） |
| `{{doc_number}}` | 文書番号（§6.3） |
| `{{issued_on}}` `{{issued_on_wareki}}` | 発信日 |
| `{{agenda.url}}` `{{opinion.url}}` | アジェンダ・意見書のその回のシート |
| `{{#proposals}}…{{/proposals}}` | 議案ごとに繰り返す。中で `{{no}}`（第N号）`{{title}}` `{{url}}` `{{presenter}}` |
| `{{#late}}…{{/late}}` | 資料配信の締切を過ぎて送るときだけ入る（「配信が遅くなり申し訳ありません」など） |
| `{{#online}}…{{/online}}` | オンラインの URL があるときだけ入る |
| `{{#first}}…{{/first}}` `{{^first}}…{{/first}}` | 繰り返しの1件目だけ／2件目から（案内文の「内　　容」の見出しなど） |

- 和暦・曜日の表記は共通の部品で作る（今の `jpdate` を使う）。
- 値がない項目（例: 文書番号を使わない LOM）は空になり、その行ごと消せる記法（`{{?doc_number}}` の行）を用意する。

### 4.3 メールの体裁

今回の失敗（プレーンテキストで崩れた）をなくすため、メールの本文は**行ごとの寄せ方を書けるレイアウト記法**で登録し、送るときに HTML と、プレーンテキストの代替本文の両方を作る。

```
[右] {{issued_on_wareki}}
{{lom.name}}
{{audience}}
[右] {{doc_number}}
[右] {{lom.name}}
[右] {{sender.title}}　{{sender.name}}

[題] {{fiscal_year}}年度 {{event.title}}開催のご案内

[字下げ] 下記の通り{{event.title}}を開催いたします。
…
[中] 記
日　　時　　　{{event.date_wareki}}　{{event.time}}
{{#proposals}}
{{#first}}内　　容　　　{{/first}}{{^first}}　　　　　　　{{/first}}{{no}}　{{title}}
{{/proposals}}
[右] 以上
```

- `[右]` `[中]` `[題]`（中央・大きく・太字）`[字下げ]`。何もなければ左寄せ。フォントと大きさは設定（既定は Google ドキュメントの既定の Arial、11pt）。
- 管理画面のプレビューは、実際に送る HTML をそのまま表示する。
- 添付（案内の PDF）は段階 D で扱う。それまでは本文に案内文を書き、アジェンダのリンクを添える。

### 4.4 LINE の文面

- テキスト（`textV2`）。`mention` が `all` なら先頭に全員へのメンション、`targets` なら対象者のうち LINE 連携済みの人へのメンション（メンションの付け方は日程調整の案内と同じ）。
- URL はそのまま本文に書く（LINE がリンクにする）。5,000 字を超えたら誤りにする。

## 5. アジェンダと意見書

### 5.1 アジェンダ

- 会議体ごとに、LOM がアジェンダの**ひな形**（Google ドキュメント）を登録する（設定 `meeting_templates[event_type].agenda_doc_id`）。ひな形には §4.2 と同じ差し込み項目を書いておく。議案の行は `{{#proposals}}` の段落を議案の数だけ複製し、議案名に資料のリンクを付ける。
- コピーは LOM 公式アカウントで作る（`app/lom_drive.py` と同じ OAuth）。オーナーが LOM になり、年度をまたいで残る。
- 置き場所は設定（`meeting_templates[event_type].agenda_folder_id`）。名前は設定の書式（既定 `{{yymmdd}}_{{event.title}}アジェンダ`）。
- 共有は設定（既定「リンクを知っている全員がコメント可」）。コピーの後に必ず付け直す（コピーでは引き継がれない）。
- 資料のリンクは台帳から作る。作業文書（`doc_id`）があればそれ、資料フォルダの議案は読んだファイル（`sources`）。同じフォルダに版が複数あるときは、最後に更新されたものを使い、画面に「どの版にリンクしたか」を出す（専務が選び直せる）。
- 担当の列（議案の説明者）は台帳の担当者・担当副理事長から作る。呼称は設定（例: 「予定者」を付けない）。

### 5.2 意見書（任意）

- 会議体ごとに、意見書のスプレッドシートと「1議案ぶんのブロック」のひな形シートを設定する。
- 準備のとき、その回のシート（名前の書式は設定。例 `2nd五役予定者会議`）を足し、議案の数だけブロックを並べて議案名を入れる。
- アジェンダ・LINE からは、そのシートへ直接リンクする（`#gid=`）。

### 5.3 書き込みの安全

- 書くのは、専務AI が作ったファイル（アジェンダ・その回のシート）だけ。委員会の議案書には書かない。
- 準備をやり直すときは、前回作ったものを同じ ID で更新する（重複して作らない。`MeetingDispatch` に ID を持つ）。

## 6. 宛先・差出人・文書番号

### 6.1 宛先

- 対象者は会議の `target_scope`（五役・理事・委員会など。今の出欠と同じ解決）。
- メール: 会員のメールアドレス（`Member.email` を足す。名簿の取込で入れる）。アドレスがない人は画面に出し、送る前に気づけるようにする。To／BCC は設定（既定 BCC。To に並べる運用の LOM は To にする）。CC に専務を入れるかも設定。
- LINE: 会議体のグループ（`Settings.line_groups`。日程調整と同じ）。グループがなければ、連携済みの対象者に個別に送る。

### 6.2 差出人

- メールは LOM 公式アカウント（`LOM_GOOGLE_ACCOUNT`）から送る。送信の権限（`gmail.send`）を足す（`scripts/gmail_oauth_setup.py --send`）。
- 文中の差出人（例: 理事長予定者 ○○）は、会議体ごとの設定（役職）から会員名を引く。

### 6.3 文書番号

- 書式は設定（例 `{{prefix}}第{{term}}-{{seq:03}}号`。`prefix` `term` は LOM が入れる）。年度ごとの連番を台帳に持ち、**メールを送ったときに確定**する（下書きや準備では番号を使い切らない。画面では「送信時に 第○-004号 を使います」と出す）。
- 手で直せる（過去の番号の続きから始めるとき）。

## 7. 送信と自動化

### 7.1 画面（管理画面「会議」の詳細に「案内・配信」）

1. 準備の状態: アジェンダ・意見書・メール・LINE のそれぞれ（未作成／作成済み／送信済み・時刻）。
2. ［配信物を準備する／更新する］。
3. プレビュー: メールは HTML のまま、LINE は吹き出しで。差し込みの結果と、値が足りない項目（Meet の URL がない、メールアドレスがない人など）。
4. ［メールを送る］［LINE に送る］。確認ダイアログに、送り先（グループ名・人数・宛先の人数）と、資料配信の締切を過ぎているかどうか（過ぎていれば `{{#late}}` の一文が入ることを出す）。
5. 送った記録（いつ・誰が・どこへ・どのテンプレート）。

### 7.2 自動で行うこと（tick）

| いつ | すること |
|---|---|
| 資料提出の締切の後の最初の tick | 配信物を準備する（アジェンダ・意見書を作り、メールと LINE の文面を作る）。送らない |
| 資料配信の締切の日の朝 | 専務に LINE で「【配信の準備】第N回○○: アジェンダ・案内の準備ができました［確認して送る］」（管理画面のその会議へのリンク）。未提出の議案があれば添える |
| 資料配信の締切を過ぎても未送信 | 専務にもう一度だけ知らせる |

- 自動で送る設定（`auto_send`）も持てるが、既定はオフ。オンにしても、宛先の足りない・テンプレートの誤り・議案0件のときは送らずに専務へ知らせる。
- 送信は今のガードレール（静音時間・送信の一時停止・1日の上限・`sanity_check`）を通す。グループへの投稿は取り消せないので、送り先のグループ名をいつも確認ダイアログに出す。

### 7.3 締切の決め方を設定にする

いまは「7・5・3日前」をコードに持っている（`reminders.BOARD_POLICY`）。LOM によって資料配信は「2日前の24:00」などと違う（今回の LOM のアジェンダにもそう書いてある）。
会議体ごとの設定（`meeting_templates[event_type].deadlines` = エントリー・資料提出・資料配信の日数と時刻）にし、催促・提出締切・配信の準備が同じ値を使う。


## 9. 既存の仕組みとのつながり

| 既存 | 使い方 |
|---|---|
| `meeting_package.build_package` | 上程議案の集め方（日程調整で決まった会議を含む）をアジェンダの議案の一覧にも使う |
| `lom_drive.copy` / `ensure_folder` | アジェンダのコピーを LOM 公式アカウントで作る |
| `committee_docs`（doc-editor） | 使わない（委員会の文書には書かない） |
| `delivery.execute_delivery` / `guardrails` | LINE の送信。メールも同じ記録（DeliveryLog）に残す |

| `proposal_submit` の締切の知らせ | 締切の設定（§7.3）を共通にする |
| `gmail`（OAuth） | 送信（`gmail.send`）を足す。取込と同じ refresh token |

## 10. 実装の段階

| 段階 | 内容 | 手作業との比較 |
|---|---|---|
| A | 通知テンプレート（データ・差し込み・既定の文面・管理画面での登録とプレビュー）。会議の「案内・配信」で LINE を送る | LINE の文面づくりが不要になる |
| B | メール（レイアウト記法 → HTML、宛先、`Member.email`、送信の権限、文書番号）。最初は「Gmail の下書きに作る」も選べる | 案内メールが体裁どおりに作れる |
| C | アジェンダのコピーと差し込み、共有の付け直し、意見書のシート | アジェンダ・意見書の作業が不要になる |
| D | 自動の準備と専務への知らせ（§7.2）、締切の設定化（§7.3）、案内の PDF の添付 | 配信の遅れに気づける |

各段階で設計書のこの節を確定させてから実装する。

## 11. 汎用にするための約束（OSS）

- LOM 名・役職名・文書番号の書式・会議体の名前・グループ・宛名は、設定かテンプレートに置く。コードに書かない。
- 既定のテンプレートは、敬語の一般的な案内文にする（「下記の通り会議を開催いたします」程度）。各 LOM は管理画面で自分の文面に直す。
- デモ環境と動画は架空の LOM・会員で作る。

## 12. テスト

- 差し込み: 項目の置き換え・繰り返し・条件の段落・知らない項目の誤り・和暦。
- メールのレイアウト記法 → HTML とプレーンテキスト（寄せ方・題・字下げ・エスケープ）。
- アジェンダ: ひな形のコピー・議案の段落の複製・リンク・共有の付け直し（Drive/Docs はモック）。
- 宛先: target_scope の解決・アドレスのない人・To/BCC・CC。
- 送信: 確認なしでは送らない・静音時間・二重送信の防止・文書番号は送信時に確定。
- tick: 準備・専務への知らせ・締切を過ぎたときの知らせが1回ずつ。

## 13. 決めたこと（2026-11-05 専務承認）

1. メールは、段階 B のはじめは「LOM の Gmail の下書きに作る → 専務が Gmail で確かめて送る」。慣れたら直接送るを選べるようにする。
2. 宛先は BCC を既定にする（To は設定で選べる）。
3. 意見書のシートの自動追加は段階 C に入れる。
4. 資料配信の締切は「2日前の24:00」を既定にする（会議体ごとの設定。§7.3）。

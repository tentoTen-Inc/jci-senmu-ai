# 資料フォルダに紐づく議案（予算書など）のチェック

2026-11-01 専務の依頼。予算書（スプレッドシート）の議案で［形式チェック］と［AI に確認してもらう］が使えなかった。

## 1. 背景

形式チェックと AI の確認は、台帳の本文（`Proposal.content`）を読む。本文は、委員会の作業文書
（`doc_id` の Google ドキュメント）から同期して入る（[proposal-ledger-design.md](proposal-ledger-design.md) §4）。

執行部の議案（予算書・理事長所信・基本計画・組織図・年間公式スケジュールなど）は作業文書を持たず、
資料の場所（`storage_uri`）として Drive のフォルダだけを持つ。資料を読む処理がないので本文は空のままで、
形式チェックは「本文が空です」、AI の確認はエラーになっていた。予算書の明細の取込は段階2としていた（同 §8）。

## 2. 対象

- `doc_id` がなく、`storage_uri` が Drive のフォルダかファイルの議案。
- フォルダなら、直下の Google ドキュメントと Google スプレッドシートをすべて読む（審議の対象が複数のファイルのことがある。
  例: 予算書の様式2つ）。サブフォルダ（「控え書類」など）と PDF は読まない。
- ファイルの URL なら、そのファイルだけを読む。

## 3. 読み取り（`app/folder_docs.py`）

- drive-reader を権限借用して読む（[drive-knowledge-design.md](drive-knowledge-design.md)。書き込みはしない）。
  資料のフォルダが drive-reader に共有されていない（`DRIVE_KNOWLEDGE_FOLDERS` の外など）ときは、読めなかったことを画面に出す。
- スプレッドシート: すべてのシートについて、表示どおりの値と数式を読む（Sheets API `values.batchGet`。
  `FORMATTED_VALUE` と `FORMULA`）。
- ドキュメント: テキストに書き出す（Drive API の export）。
- 台帳の本文に、ファイルごと・シートごとに「【ファイル名／シート名】」の見出しを付けて写す。表は空の行と列を詰め、
  セルを「 | 」でつないだ1行にする。長すぎるときは上限（60,000字）で切り、切ったことを書く。
- 読むのは［形式チェック］［AI に確認してもらう］［提出する］のとき（いつも最新を読む）。1時間ごとの同期はしない。

## 4. 形式チェック

スプレッドシートは**自動では直さない**。金額にかかわるので、表示形式も含めて作る人が直す（「直す点」として出す）。
どの点も「ファイル名・シート名・セル番地」を添える。

| チェック | 内容 |
|---|---|
| 数式のエラー | `#REF!`・`#DIV/0!`・`#VALUE!`・`#N/A`・`#NAME?`・`#NUM!`・`#ERROR!` のセル |
| 古い年の表記 | 「YYYY年M月D日から」の期間が議案の年度と違う。議案の年度より2年以上前の年の表記（前年度との比較の列があるので、前年は対象外） |
| 合計の手入力 | 項目名に「計」「合計」「小計」を含む行で、金額が数式でなく数字で入っている（直したときに合計がずれる） |
| 文字として入った数字 | 数字に見えるが文字として入っているセル（全角数字、「10,000円」など）。合計の計算に入らない |

- 議案の年度は、議案名の「2027年度」から取る。なければ台帳の年度、それもなければ運用開始日の年。
- ドキュメントの部分は、これまでどおり表記（全角英数字・記号）を調べる。スプレッドシートの項目名（「１．事業活動収入」など様式の文字）は対象にしない。
- 必須項目のチェックは、予算書などの種類には設けない。

## 5. AI の確認

- 本文（§3 で写したもの）を読み、要約・論点・気になる点を出す（今の AI の確認と同じ形・同じモデル `proposal_review`）。
- 議案の種類が予算書のときは、次の観点を指示に加える。
  - 収入の合計と支出の合計（収支差額）
  - 前年度から大きく増減した科目のうち、備考に理由が書かれていないもの
  - 予備費の割合
  - 委員会ごとの事業費と、年間の事業（例会・事業の数）との食い違い
  - 複数の様式（例: 収支予算書と正味財産増減予算書）で、同じ科目の金額が食い違っていないか
- ほかの種類（理事長所信など）は、今の議案の観点のまま。

## 6. 画面

- 議案の詳細の「議案書のチェック」に、読んだファイルの一覧（名前とリンク）を出す。
- 資料の場所が未設定・読めないときは、エラーではなく「資料を読み取れませんでした（理由）」を出し、AI の確認は押せないことを示す。
- 形式チェックの結果は、今の「委員会で直す点」と同じ欄に出す（執行部の議案は「直す点」と表示する）。

## 7. 個人情報

組織図などは会員の氏名を含む。台帳の本文はこれまでも議案書の全文を持っており、AI の確認は同じ Vertex AI
（自分の LOM の Google Cloud。学習に使われない）で行うので、扱いは今の議案書と同じ。名簿・住所録はフォルダに置かない運用とする。

## 8. テスト

`tests/test_folder_docs.py`: フォルダの読み取り（ファイルの種類・サブフォルダを読まない・読めないとき）、本文への写し方と上限、
4つのチェック（エラー・年・合計の手入力・文字の数字）、年度の取り方、予算書の AI の指示、API と画面に返す値。

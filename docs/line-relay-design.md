# 外部グループからの周知の転送（F5 拡張）詳細設計書 v0.1

最終更新: 2026-11-26
前提: 対外連絡 `docs/external-notice-design.md`（F5）、データレイク `docs/datalake-design.md`、
チャットの原則（書き込みはボタンからだけ）

---

## 1. 目的

ブロック協議会などが各 LOM に向けて「メンバーに展開してください」と投稿する LINE グループ
（以下「取込元グループ」）がある。いまは専務がそれを読み、自分の LOM のグループへ手で貼り直している。

これを次の流れに置き換える。

```
[取込元グループ] ──投稿──► ボット（グループに参加済み・発言はしない）
                                  │ ① 取り込む（原文のまま記録）
                                  │ ② AI が「LOM への単なる周知依頼か」を判定
                                  ▼
                       [専務の個人 LINE] 確認カード
                         原文／送信先／転送する文面
                         ［送る］［送らない］［管理画面で直す］
                                  │ ③ 専務が［送る］→［送信する］の2段階で承認
                                  ▼
                       [LOM のグループ]（@All で転送）
```

### 設計の芯
1. **専務の承認なしには一切送らない。** グループへの送信は取り消せない（LINE の仕様）。
   ボタンは2段階（［送る］→ 送信先のグループ名を示して［送信する］）。
2. **転送する文面は原文のまま。** AI は判定と1行の要約（確認カード用）だけに使い、本文を書き換えない。
   URL・期限・依頼の言い回しが変わる事故を防ぐ。冒頭に出所の見出しを付けるだけ。
3. **既存の部品を使う。** 記録は対外連絡（`ExternalNotice`）、専務への通知は `sed_notice`、
   グループへの投稿は予約投稿（`ScheduledPost`）、配信のガードレール（静音時間・キルスイッチ）もそのまま。
4. **取込元は管理画面で指定したグループだけ。** ボットがいるグループを勝手に取込元にしない。
   LOM 固有の値（グループ名・ID）はコードに書かない（全国の LOM で使えるように）。

## 2. 取り込み

### 2.1 取込元グループの指定
`LineGroup` に `relay_source: bool`（取込元）と `relay_label: str | None`（見出しに使う出所名。例「〇〇ブロック協議会」）を足す。
管理画面の「LINE グループ」一覧で切り替える。転送先は `Settings.relay_target_group_id`（LOM 全体のグループ）。

### 2.2 受け取り
データレイクのワーカー（`line_worker.handle_envelope`）で、取込元グループの `message` イベントを拾う。
- テキスト: そのまま記録する。
- 画像・PDF: いまは「会員でない人のファイルは保存しない」が、**取込元グループに限って保存する**
  （転送のため）。PDF はテキストも抜き出す（既存の `store_content`）。

### 2.3 連投をまとめる
ブロックからの依頼は「本文の投稿」と「共有します、の一言」が数分おきに続くことが多い。
同じ送り主・同じグループで **10分以内** に続いた投稿を1件の連絡にまとめる。
ワーカーは投稿を「まとめ中」として溜めるだけにし、確定は Cloud Scheduler から5分おきに呼ぶ
`/tasks/relay` が行う（最後の投稿から10分たったものを確定 → 判定 → 確認カード）。
毎時の tick に相乗りしないのは、転送が最大1時間遅れるため。`/tasks/relay` は判定と確認カードの送信だけで軽い。
静音時間のあいだは確定・判定までにとどめ、確認カードは静音時間明けに送る。

確定した連絡は `ExternalNotice` として保存する。
```
  source: "line_group"
  source_ref: "<group_id>:<最初の message_id>"   # 冪等キー
  from_name: 送り主の表示名（グループのプロフィール。取れなければ None）
  subject: 本文の1行目（40字まで）
  body_text: まとめた本文（原文・不変）
  attachments: 画像・PDF（storage_uri）
  relay: NoticeRelay（下記）
```

## 3. 判定（AI・助言）

Gemini Flash（会員対応と同じ軽いモデル。`llm.TASK_MODELS` に理由付きで登録）で次を返す。

| 項目 | 内容 |
|---|---|
| `kind` | `share`（メンバーへの周知依頼）／`officer`（理事長・役員あての依頼）／`other`（お礼・雑談・返信など） |
| `summary` | 確認カードに出す1〜2行の要約 |
| `deadline` | 期限があれば |

- `share` だけ確認カードを専務に送る。
- `officer` は専務に「役員あての依頼が届きました」と知らせるだけ（転送ボタンなし。必要なら管理画面から転送できる）。
- `other` は記録だけ（対外連絡一覧に「対象外」として残る）。

判定は助言。誤って `other` になったものも管理画面から転送できる。

## 4. 確認と送信

### 4.1 確認カード（専務の個人 LINE）
送る相手は `officer_role` が専務理事の会員（`sed_notice` と同じ）。

```
【転送の確認】〇〇ブロック協議会のグループから
要約: 本会の運動方針動画の視聴とアンケート回答のお願い（回答率が低いため）
送信先: <LOM 全体のグループ名>
――― 転送する文面 ―――
【〇〇ブロック協議会より】
（原文そのまま）
――――――――――――
［送る］［送らない］［管理画面で直す］
```
- 文面が長い（LINE の上限に近い）ときは、カードには先頭だけを出し、全文は管理画面へ。
- ［送る］→「<グループ名> に @All で送ります。取り消せません。」［送信する］［やめる］
- ［送信する］で予約投稿（`ScheduledPost`, kind=`relay`, send_at=今）を作り、その場で送る。
  静音時間なら朝8時に送ると返事をする。
- ［送らない］で `status=archived`。
- 7日たっても押されなければ期限切れ（カードのボタンは無効、管理画面には残る）。
- ボタンを押せるのは承認者だけ。ほかの人が押したら何もしない。

### 4.2 転送する文面
```
@All
【<relay_label>より】
<原文>
```
画像・PDF があれば続けて送る（画像はそのまま、PDF はファイル名とリンク）。

### 4.3 記録
`NoticeRelay`
```
  kind: share | officer | other
  summary: str
  card_sent_at: datetime | None
  approved_by: member_id | None
  approved_at / sent_at: datetime | None
  target_group_id: str
  post_id: str | None   # ScheduledPost
  expired_at: datetime | None
```
監査ログ: `notice.relay.card` / `notice.relay.approve` / `notice.relay.sent` / `notice.relay.reject`。

## 5. 管理画面

- 「対外連絡」一覧に出所「LINE グループ」を加え、判定（周知・役員あて・対象外）と転送状況を表示。
- 詳細で文面を直して転送できる（既存の配信画面に「グループへ転送」を足す）。
- 「LINE グループ」一覧で取込元の指定と出所名、設定で転送先グループを選ぶ。

## 7. 決まったこと（2026-11-26 専務）

1. 転送先は LOM 全体のグループ1つ。理事会・五役あてに送りたいときは管理画面から送る。
2. 役員あての依頼（例:「各 LOM 理事長の皆様」）は専務に知らせるだけ（転送ボタンなし）。
3. 転送する文面は「@All」＋「【<出所名>より】」＋原文そのまま。AI は本文を書き換えない。
4. 夜間（静音時間）に届いたものは翌朝に確認カードを送る。承認の待ち期限は7日。
